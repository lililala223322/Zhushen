# 迷海寻宝模拟与策略优化 Goal

> 本文件用于指导 Goal 模式持续推进任务。需求来源为同目录下的 `task.md` 以及后续确认内容。
>
> 工作范围严格限定在 `迷海/`。除非用户后续明确扩大范围，不读取、不修改其他业务目录。

## 1. 最终目标

构建一个可信、可复现、带实时可视化的迷海寻宝模拟与策略优化工具，并产出足够完整的数据报告，帮助用户决定实际游戏中何时重置地图。

核心成果必须同时包含：

1. 正确模拟固定25格奖池、碎片收益和最多13次重置。
2. 以“完成600碎片所需的操作1次数”为唯一成本。
3. 重点搜索和评估进取型策略，而不局限于最初列出的碎片排列组合。
4. 在模拟运行过程中实时展示成本分布；默认每完成10,000局重绘一次。
5. 对未知抽奖机制做多模型敏感性分析，不把未经证实的模型描述成游戏事实。
6. 输出均值、置信区间、完整分位数、尾部风险、重置使用情况、模型敏感性及策略间成对比较。
7. 最终给出简单、可执行、可解释的玩家操作规则，而不仅是程序内部的策略对象。

## 2. Goal 模式推进规则

Goal 模式开始后应遵循以下规则：

1. 先阅读本文件和 `task.md`，从第一个未完成里程碑继续，不重复已经验证完成的工作。
2. 在安全、可逆且属于本任务范围的情况下自主推进，不因实现细节频繁暂停。
3. 每完成一个里程碑，都运行相应测试并记录结果；测试未通过不得把该里程碑标为完成。
4. 探索用随机种子与最终评估种子必须分离，不能一边用同一批结果调参，一边把它当作最终证据。
5. 不得仅凭蒙特卡洛结果宣称“全局最优”。如果只搜索了有限策略族，应表述为“当前搜索空间内最优”。
6. 只有当实现、实时可视化、正式模拟、敏感性分析、数据导出和最终报告全部完成后，才可以将 Goal 标记为完成。
7. 若发现本文件中的假设与用户新提供的事实冲突，以用户最新事实为准，并同步更新本文件中的假设记录。

## 3. 已固定的业务规则

### 3.1 目标与成本

- 初始宝图碎片：0。
- 目标宝图碎片：至少600。
- 操作1“打开格子”：成本记为1。
- 操作2“重置地图”：成本记为0。
- 操作2最多使用13次。
- 达到或超过600碎片后立即停止，不做多余操作。
- 除宝图碎片外，其他奖励不计入策略价值。

### 3.2 单张地图

- 每张地图有25格。
- 每次操作1固定获得2个宝图碎片。
- 奖池内另有三份碎片奖励：5、15、30。
- 完整打开一张地图固定获得：

```text
25 × 2 + 5 + 15 + 30 = 100
```

- 从零开始完整打开六张地图固定需要150次操作1，因此150是确定性的基准成本。
- 开完地图但尚未达到目标时，必须有剩余重置次数才能进入下一张地图。

### 3.3 奖池数据

奖池以 `task.md` 中的25行数据为准。实现时应转换为22个类别，其中：

- 辉石3：库存2。
- 辉石5：库存2。
- 灵魂水晶：库存2。
- 其他类别：库存1。

22个类别的展示概率之和必须恰好为100%；按25份逐行相加则为113.09%。

## 4. 优化口径

这是一个随机环境，不能仅用单局中的“最少”定义策略优劣。正式采用以下分层目标：

1. **硬约束：完成率必须为100%。**
   - 策略不得过早耗尽13次重置，使600碎片变得不可达。
   - 任何失败局都视为策略不合格，而不是给失败局分配一个有限成本。
2. **主目标：最小化操作1次数的期望值 `E[N]`。**
3. **第一辅助目标：降低P95和P99，避免均值很好但尾部很差。**
4. **第二辅助目标：提高相对150次基准的胜率，并降低超过150次的概率。**
5. **可解释性目标：性能接近时优先选择规则更简单、更适合玩家手动执行的策略。**

若两个策略的期望差异没有统计显著性，则依次比较：

1. P95；
2. P99；
3. 超过150次的概率；
4. 规则复杂度。

## 5. 未知抽奖机制与三种模型

当前公开信息不足以确认游戏内部抽奖算法。正式工具必须支持以下三种模型，并在界面和报告中明确标注“假设模型”。

### M1：类别权重、耗尽后重抽（主模型）

设类别 `i` 的展示概率为 `p_i`，剩余库存为 `c_i`。

```text
P(i | 当前奖池) = p_i / Σ p_j
```

求和仅包含 `c_j > 0` 的类别。

- 有两份库存的类别在抽走第一份后仍保留完整类别权重。
- 第二份抽走后，该类别才从候选集合移除。
- 这是 `task.md` 当前假设的精确定义。

### M2：每份物品分别带权

```text
P(i | 当前奖池) = c_i × p_i / Σ(c_j × p_j)
```

重复类别在初始状态拥有两倍类别权重，抽走一份后降为一倍。

### M3：固定奖池均匀洗牌

```text
P(i | 当前奖池) = c_i / Σ c_j
```

等价于每张地图开始时将25份物品均匀随机排列。

### 模型使用原则

- M1作为策略搜索和主结论模型。
- M2、M3用于敏感性分析。
- 最终报告必须同时展示同一策略在三种模型下的表现。
- 如果某策略仅在M1中有效、在其他模型明显恶化，必须显著提示。
- 推荐策略优先考虑跨模型稳健性，但主排序仍以M1的期望成本为准。

## 6. 策略体系

### 6.1 必须实现的基线策略

1. `full_clear`
   - 每张地图全部打开。
   - 结果必须恒为150次操作1。
2. `reset_on_5`
3. `reset_on_15`
4. `reset_on_30`
5. `reset_on_5_and_15`
6. `reset_on_5_and_30`
7. `reset_on_15_and_30`
8. `reset_on_all_fragments`
9. 如有必要，增加“取得任意一个指定碎片即重置”和“取得所有指定碎片才重置”两种语义，界面中不得混淆。

所有基线策略也必须经过可完成性护栏，不能产生无法完成的局。

### 6.2 进取型状态策略

主策略不能只看碎片组合，至少应使用以下状态：

```text
totalFragments       当前累计碎片
resetsRemaining      剩余重置次数
depth                当前地图已打开格数
fragmentMask         当前地图已取得的5/15/30碎片位掩码
remainingInventory   当前地图剩余奖池
```

碎片位掩码定义：

```text
1 = 已取得碎片5
2 = 已取得碎片15
4 = 已取得碎片30
```

### 6.3 可完成性护栏

若当前累计碎片为 `S`，执行重置前剩余重置次数为 `R`，则重置后最多还有 `R` 张完整地图可用。重置至少必须满足：

```text
S + 100 × R >= 600
```

不满足时禁止主动重置，继续打开当前地图。

实现还应检查更精确的剩余容量，确保：

- 重置次数永不超过13。
- 不会在最后一张地图耗尽后仍未达到600。
- 每个被正式比较的策略失败率严格为0。

### 6.4 初始进取型阈值

以下阈值来自前期探索，只作为优化起点和回归参考，不是最终结论。

当当前状态在相应深度以内首次满足条件时，可以考虑重置：

| 当前地图已取得的碎片 | 深度阈值 |
|---|---:|
| 只有5 | 2 |
| 只有15 | 5 |
| 5和15 | 6 |
| 只有30 | 13 |
| 5和30 | 14 |
| 15和30 | 18 |
| 5、15、30全部取得 | 25，即总是考虑重置 |
| 尚未取得碎片 | 0，即不重置 |

任何重置仍须通过可完成性护栏。

### 6.5 策略优化方向

至少依次尝试以下搜索空间：

1. **8状态深度阈值**
   - 为每个 `fragmentMask` 搜索最佳深度阈值。
2. **加入剩余重置次数分段**
   - 例如 `0–2`、`3–5`、`6–9`、`10–13`。
3. **加入距离目标的碎片缺口分段**
   - 例如 `1–100`、`101–200`、`201–400`、`401–600`。
4. **加入当前地图剩余碎片价值**
   - 剩余5、15、30的组合。
5. **有限深度前瞻或蒙特卡洛 rollout**
   - 比较“现在重置”和“至少再开一格”的期望剩余成本。

策略搜索应优先采用：

- 网格搜索；
- 坐标下降；
- 随机搜索或交叉熵搜索；
- 必要时使用近似动态规划或rollout。

不得在没有证明的情况下把参数搜索结果称作全局最优策略。

### 6.6 进取版与保守参照

最终主推荐选择进取版，即以最低期望操作1为主。

同时保留一个保守参照策略：

- 通过最坏情况预算护栏保证总成本不超过150。
- 用于展示“降低均值”和“限制尾部风险”之间的代价。
- 保守版不与进取版争夺主推荐，但必须出现在最终比较数据中。

## 7. 实时可视化要求

推荐实现为本地网页仪表盘。默认技术路线：

- TypeScript；
- Vite；
- React；
- Apache ECharts；
- Web Worker执行模拟；
- Vitest执行单元和统计测试。

若依赖或环境限制导致该路线不可行，可以改用等价技术，但不得牺牲实时更新、交互性、可复现性和数据导出。

### 7.1 模拟批次

- 默认正式模拟总局数：1,000,000局/策略/模型。
- 默认批次大小：10,000局。
- 每完成一个批次，Worker向界面发送一次聚合快照。
- 界面收到快照后重绘图表和统计表。
- 批次大小允许配置，例如1,000、5,000、10,000、50,000。
- 重绘频率不得阻塞模拟；必要时合并过于密集的界面更新。

### 7.2 必须提供的控制项

- 抽奖模型：M1/M2/M3。
- 策略多选。
- 目标碎片数，默认600。
- 最大重置次数，默认13。
- 总模拟局数，默认1,000,000。
- 更新批次，默认10,000。
- 主随机种子。
- 启动。
- 暂停。
- 继续。
- 停止。
- 重置结果。
- 导出数据。

界面必须实时显示：

- 已完成局数；
- 总局数；
- 完成百分比；
- 当前批次；
- 模拟速度（局/秒）；

### 7.3 核心图：成本分布

这是最高优先级图表。

- 横轴：完成600碎片所需的操作1次数。
- 纵轴默认：恰好落入该成本的模拟局数，以柱状图显示。
- 支持切换为累计概率 `P(N ≤ x)`，以阶梯线显示；成本x处必须等于所有成本不超过x的概率之和。
- 成本为整数时默认箱宽为1。
- 每10,000局更新一次。
- 支持多个策略叠加、分面显示和显隐切换。
- 标出：
  - 均值；
  - 中位数；
  - P90；
  - P95；
  - P99；
  - 150次全开基准线。
- 鼠标悬停在局数模式显示该成本的单点次数，在累计概率模式显示截至该成本的累计比例。
- 支持缩放查看尾部。

### 7.4 必须提供的其他图表

1. **主图累计概率模式（CDF）**
   - `P(N ≤ x)`，直接集成在核心成本分布图中。
   - 用于回答“在多少次操作内完成的概率是多少”，不再另画一张重复CDF图。
2. **尾部生存曲线**
   - `P(N > x)`，建议使用对数纵轴选项。
3. **均值收敛图**
   - 横轴为累计模拟局数。
   - 纵轴为累计均值及95%置信区间。
4. **关键分位数收敛图**
   - 展示P50、P90、P95、P99随样本量的变化。
5. **策略差值分布**
   - 横轴为 `进取策略成本 - 基线策略成本`。
   - 小于0表示进取策略节省操作。
6. **重置次数分布**
   - 展示0至13次重置的次数和比例。
7. **成本×重置次数热力图**
   - 用于判断低成本是否依赖大量重置。
8. **地图使用数量分布**
   - 展示完成目标时共进入多少张地图。
9. **最终碎片溢出量分布**
   - `最终碎片 - 600`。
10. **三种碎片奖励获取次数分布**
    - 分别统计5、15、30碎片被取得的次数。
11. **策略决策热力图**
    - 横轴为地图深度。
    - 纵轴为碎片状态或剩余重置次数。
    - 颜色表示继续/重置，或重置概率。
12. **模型敏感性图**
    - 同一策略在M1/M2/M3下的均值、P95和P99并列比较。
13. **相对基线收益图**
    - 展示平均节省次数、胜/平/负比例及超过150次的概率。

## 8. 策略成对比较

最终决策不能只看各策略独立均值。必须提供成对比较：

- 平均成本差；
- 成本差的标准误和95%置信区间；
- 中位成本差；
- 进取策略胜率；
- 平局率；
- 负率；
- 平均胜出幅度；
- 平均落后幅度；
- 最大观察胜出幅度；
- 最大观察落后幅度；
- P95差值；
- `P(进取策略成本 > 150)`；
- `P(进取策略比full_clear多至少5次)`；
- `P(进取策略比full_clear少至少5/10/20次)`。

为降低策略比较噪声，同一局编号、同一模型应使用相同的底层地图序列：

```text
mapSeed = hash(masterSeed, episodeIndex, mapIndex, modelId)
```

每个策略在第 `mapIndex` 张地图看到相同的完整抽取顺序。策略可以只消费该顺序的前缀并重置。这样既保证公平，又使成对差值更有解释力。

## 9. 随机性与可复现性

### 9.1 确定性要求

- 使用明确记录的伪随机数生成器及版本。
- 相同配置、相同种子必须得到逐项一致的结果。
- 每局、每张地图使用可独立派生的种子。
- 改变Worker数量、批次大小或暂停/继续次数，不得改变最终结果。
- 不使用系统时间隐式改变正式模拟种子。

### 9.2 训练集与评估集

- 策略调参使用训练种子集合。
- 候选筛选使用验证种子集合。
- 最终报告使用从未参与调参的测试种子集合。
- 三套种子和生成规则都必须写入运行元数据。
- 最终报告不得混用训练结果与测试结果。

### 9.3 样本量与停止条件

- 探索阶段可以从10,000或100,000局开始。
- 正式阶段至少1,000,000局/策略/模型。
- 若进取策略与次优策略的均值差小于0.1次，应增加样本量，直到：
  - 差值95%置信区间不跨0；或
  - 达到预设最大样本量后明确报告“无法区分”。
- 建议正式均值置信区间半宽不超过0.03次操作。

### 9.4 流式统计

为了避免保存海量逐局数据：

- 操作成本使用整数直方图精确累计。
- 重置次数、地图数、溢出量也使用整数计数表。
- 均值、方差、协方差、偏度、峰度使用稳定的在线算法。
- 分位数优先从精确整数直方图计算。
- 成对策略差值使用独立差值直方图和在线矩。

设计约束：

- 模拟核心必须是纯逻辑，不依赖DOM。
- 策略通过统一接口接收状态并返回 `open` 或 `reset`。
- 模型通过统一接口生成下一奖励或整张地图顺序。
- UI不得复制模拟规则。
- Worker只发送聚合快照，避免每局消息拖慢模拟。
- 所有策略定义都必须能序列化并导出。
